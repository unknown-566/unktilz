# unktilz

A web toolbox: Minecraft utilities, dev tools, file converters and everyday helpers. Vite + React + TypeScript, static build, everything runs in the browser. Made for desktop browsers.

## Getting started

1. Install [Node.js](https://nodejs.org) (the LTS version; 18 or newer).
2. Get the code: `git clone https://github.com/unknown-566/unktilz.git`, or on GitHub click **Code → Download ZIP** and unzip it.
3. Open a terminal in the project folder and run:

```bash
npm install       # once, downloads the dependencies
npm run dev       # http://localhost:5173
npm run build     # typecheck + production build into dist/
npm run preview   # serve dist/ locally
```

### Windows without the terminal

- **`start.bat`**: double-click to run the site; the browser opens by itself. If Node.js is missing it offers to install it (winget, Node.js LTS), and the first run installs the dependencies. Closing the black window stops the site. It runs the built site (`vite preview` on port 5173), which is much faster than the development server: `scripts/ensure-build.mjs` rebuilds `dist/` first only when it's missing, a source file is newer than the last build, or `package.json` has another version (so the first start after an update takes about half a minute). `start.bat dev` runs the development server instead.
- **`update.bat`**: double-click to update to the newest version from GitHub and start it. Works for a ZIP download (no Git needed) as well as a `git clone`. It replaces the site's own files (`src/`, `public/`, …) and leaves `node_modules` and any of your own extra files alone.

### Windows: folder paths with `&`

npm’s launcher scripts break when the folder path contains `&` (e.g. `Minecraft & games\unktilz-main`): you get “… is not recognized as an internal or external command” and “Cannot find module …\vite\bin\vite.js”. `start.bat` works around it by starting Vite with `node` directly; for `npm run …` commands, move the folder to a path without `&`.

### Windows: “running scripts is disabled on this system”

PowerShell blocks `npm` by default, because there `npm` is a script (`npm.ps1`). Any one of these fixes it:

- Type `npm.cmd` instead of `npm`, e.g. `npm.cmd install` and `npm.cmd run dev`.
- Use **Command Prompt** (cmd) instead of PowerShell; plain `npm` works there.
- Allow local scripts for your user account once (then plain `npm` works in PowerShell too):

  ```powershell
  Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
  ```

  This changes a Windows security setting for your account only: your own scripts run, downloaded ones must be signed.

`design/` holds the original mockups and `HANDOFF.md` the spec. They are reference only and are not part of the build.

## Deploying

`dist/` is a static site, but routes like `/t/audio-converter` need an SPA fallback: every unknown path should serve `index.html`.

- Netlify: add `/* /index.html 200` to `public/_redirects`
- Vercel: a rewrite of `/(.*)` to `/index.html`
- GitHub Pages: copy `dist/index.html` to `dist/404.html` after building

The resource pack maker's sounds, other languages and menu panorama come through `/mc-assets/<2 hex>/<sha1>` (a pass-through to `https://resources.download.minecraft.net/`, also in `vite.config.ts`); a static host needs the same rewrite, or those parts say they need the site's own server.

GIF links (the GIF maker's "Make a link") upload through the `/upload/catbox` and `/upload/litterbox` proxies in `vite.config.ts`, so they only work where Vite serves the site (`npm run dev`, `npm run preview`, start.bat). A static host needs the same two rewrites to `https://catbox.moe/user/api.php` and `https://litterbox.catbox.moe/resources/internals/api.php`, or the GIF maker says links aren't available.

Everything in `dist/assets/` has its content hash in the file name, so it can be cached for good: `vite preview` (and so start.bat) sends `Cache-Control: public, max-age=31536000, immutable` for `/assets/*` (the `cacheAssets` plugin in `vite.config.ts`), and `index.html` stays `no-cache` so a new version shows up right away. Do the same on a static host.

The site's fonts (Geist, Geist Mono) come from `@fontsource-variable` packages and ship with the site; nothing is loaded from Google Fonts except the GIF maker's online font list.

The ffmpeg core (`ffmpeg-core-*.wasm`, about 32 MB, about 10 MB gzipped) only downloads the first time someone runs an audio or video job. It uses the single-threaded core, so no COOP/COEP headers are needed.

Things that don't work in this ffmpeg.wasm build (0.12.10), and what's used instead:

- `libvpx-vp9` crashes ("memory access out of bounds"): WebM video uses VP8 (`libvpx`).
- `libopus` crashes on stereo: Opus uses ffmpeg's own encoder (`-c:a opus -strict -2 -ar 48000`).
- `loudnorm` needs `aformat=sample_fmts=fltp` right after it, a fixed sample format at the end of the chain and `-ar` (not an `aresample` filter), or the encoders fail.
- After any failed run the instance is unreliable, so `ffmpegJob` throws it away and the next attempt or job loads a fresh one.
- Its wasm memory only grows, so the instance is also thrown away 30 seconds after the last job (`hold`/`letGo` in `src/lib/ffmpeg.ts`); the next job loads it again from the browser cache in about a second.

Other file libraries, all loaded only when a job needs them: pdf.js (`pdfjs-dist` 6, Apache-2.0) draws PDF pages (`src/lib/pdfjs.ts`; documents are closed with `closePdf`, since pdf.js 6 frees them through the loading task), pdf-lib (MIT) writes PDFs (only inside the compute worker, `src/workers/tasks/pdf.ts` and its neighbours, so it's downloaded once), libheif-js (LGPL-3.0) reads HEIC photos and utif2 (MIT) reads TIFF.

## Translations (English / Czech)

The site is English by default; the `lang: en` button in the header switches it to Czech (remembered in `localStorage` as `unktilz-lang`, and a switch reloads the page).

- **In code, the English text is the key:** `t('Save PDF')`, with values `t('{n} of {all}', { n, all })` (`src/lib/i18n-core.ts`, no React, so workers use it too). A sentence with a link or bold part in it is translated whole with `tn('Run {command} to …', { command: <code>…</code> })` (`src/lib/i18n.ts`), so the word order can change. Numbers use `plural(n, ['{n} file', '{n} files'], ['{n} soubor', '{n} soubory', '{n} souborů'])` (Czech has three forms) and `fmtNum` / `fmtDate` / `fmtTime`. A short word that means different things in different places gets a context: `t('theme|dark')` shows "dark" in English.
- **Texts kept in constants** (lists of choices…) are translated when their module runs: `main.tsx` sets the language (and loads the dictionary) before it imports the app, so plain `t()` works there too. `tx('…')` only marks a text for the check, for lists shown later with `t(label)`.
- **The Czech dictionary** is `src/i18n/cs/` (one file per area, `index.ts` joins them). It loads as one chunk (about 65 kB gzipped) only when Czech is picked; a missing entry shows the English text, and in development it's logged as `[i18n] missing Czech for: …`. Style: polite "vy", plain and short, and the same words everywhere (the glossary at the top of `app.ts`). Minecraft's own names (blocks, items, enchantments, biomes, structures, chat colours, the item tooltip preview) and generated files, commands and QR contents stay English.
- **Search** ignores accents and letter case, and in Czech it also looks in each tool's Czech search words (`src/i18n/cs/keywords.ts`, entry `keywords:<slug>`): other word forms and other words for the same thing. A new tool needs its line there; the check below says when it's missing.
- **The compute and background-remover workers** get the page's language with every job, so their messages come translated. The downloader's server answers in English; its own messages are translated on the page (`serverText` in `src/tools/video/downloader/api.ts`).
- **`npm run i18n:check`** (`scripts/i18n-check.mjs`, rules in `scripts/i18n-rules.mjs`) parses the code with TypeScript and fails when a text in `t()` has no Czech entry, when the `{values}` differ, or when a text people read isn't in `t()` at all (JSX text, `title` / `placeholder` / `aria-label`…, labels and help in objects, error messages, dialogs). `// i18n-ignore` skips a line, `// i18n-ignore-file` a file; a dictionary file's `SAME` list names texts that read the same in Czech. `--list` prints everything, `--suspects` other strings that look like words, and `--fix FILE…` wraps the plain cases in `t()` for you (and lists the sentences it can't).

## Adding a tool

Make one `*.tool.ts` file anywhere under `src/tools/` that default-exports `defineTool({...})`. The registry picks it up through `import.meta.glob`. The home page, search, category chips and related links are all generated from it.

- **File tools** set `accepts`, `options` and `run`. `run(files, opts, { signal })` returns an async iterable of `{ type: 'progress', value }` and `{ type: 'result', name, blob }`. Heavy work goes to a worker: `ffmpegJob()` in `src/lib/ffmpeg.ts` (ffmpeg.wasm has its own worker), or `compute()` in `src/lib/compute.ts`, which sends a task to `src/workers/compute.worker.ts` (tasks live in `src/workers/tasks/`). Set `batch: true` when all the chosen files should become one job (merges). Set `reverse` to the opposite tool's slug to get the swap button. Set `added: 'YYYY-MM-DD'` on a new tool to give it a "new" tag for 5 days (`isNew` in `src/registry/types.ts`), and `beta: true` while it's still being tested. Both also feed the New / Beta filter chips on the home page (`?tag=new,beta`; a chip with no tools is hidden). When a tool is folded into another, add its old slug to `ALIASES` in `src/registry/index.ts` so old links still open the right tool.
- **Interactive tools** set `component: lazy(() => import('./MyTool'))`. Use the pieces in `src/components/ui.tsx` (Panel, Segmented, Toggle, Output, Stat…) so the tool matches the rest. A tool that starts from files takes them with `DropZone` (`src/components/DropZone.tsx`, the same one the file tools use; `more` once files are in). Links to other pages of the site use `GoLink` from `src/components/Transition.tsx` (a react-router `Link` that opens the page through the block transition). 3D views use three.js, loaded lazily (see the shape generator's `Shape3D.tsx` / `shapeScene.ts`); call `forceContextLoss()` when disposing, browsers allow only a few WebGL contexts.
- **When a page breaks:** every page sits inside an `ErrorBoundary` (`src/components/ErrorBoundary.tsx`, set up in `src/App.tsx`), so an error while a tool draws shows `PageError` (reload, try again, all tools, the error text under details) instead of an empty site; the header, the queue and the footer keep working, and opening another page starts fresh. A part of a tool that may fail on odd data (a 3D view, an editor) can have its own `ErrorBoundary` with a `resetKey` and a small `fallback`. Errors in click handlers and timers don't reach it; handle those where they happen.
- **Texts** people read go through `t()` and get a Czech entry in `src/i18n/cs/` and Czech search words in `src/i18n/cs/keywords.ts` (see Translations above); `npm run i18n:check` lists what's missing.

Option types are `choice` (segmented buttons), `multi` (the same buttons, any number pressed; the value is the picked values joined by commas, in the choices' order, `""` for none), `range`, `number`, `text` and `toggle`. Any option can take `when: (opts) => boolean` to hide itself.

## How the queue works

- `src/queue/store.ts` is a Zustand store persisted to IndexedDB. Job metadata is written on every change. Input and output files go into their own IndexedDB store once (`src/queue/blobs.ts`).
- `src/queue/runner.ts` runs one job at a time in the order they were added, on whatever page is open. A job that was running when the tab closed starts over on the next load.
- Removing a running job aborts it: the ffmpeg instance or compute worker is terminated and a fresh one is made for the next job.
- **Tasks** are jobs a tool page makes from what it has in memory, which can't be saved to IndexedDB (the GIF maker's video frames and stickers). `useQueue.getState().addTask(info, run, release)` queues them; the work itself lives only in memory (`src/queue/tasks.ts`), runs in turn with the other jobs, and its outputs are stored like any job's. `release` runs when the task is over (done, failed or removed). A task can't survive the tab closing: on the next load it shows as failed, unless it says how to carry on. `addTask(info, run, release, { kind, data })` saves `resume` with the job, the run can update its data with `keep(data)` (its third argument), and after a reload the runner gets the work back from `src/queue/resume.ts` (kind → the tool's module, loaded lazily). The downloader uses it: a download keeps running in yt-dlp while the page reloads (switching the language reloads it too), so the job follows the server's job again by its id, or starts if it was still waiting. Switching the language asks first when tasks that can't carry on are running (`Header.tsx`).
- The GIF maker frees its frames, photos and stickers through `whenFree()` (`src/tools/image/gif-maker/hold.ts`), which waits while a GIF that uses them is queued or being made, even after leaving the page.
- **Results go on to other tools** (`src/queue/dragFiles.ts`). A finished job in the queue rail (and its row under a file tool) can be dragged: the drag carries only the job's id as `application/x-unktilz-output` (a drag can't hold the files, which sit in IndexedDB), plus a `DownloadURL` for one file so it can also be dropped into a folder (its blob URL is made on hover, as a drag needs it at once). Chat apps like Discord ignore a DownloadURL, so a finished picture shows in its queue tile (and as the thumbnail under a file tool) as an `<img>`: dragging that picture makes Chrome carry the file itself, and then no DownloadURL is set, as it would replace it (`isPictureJob`). Desktop apps such as the Discord app take neither (they want a real file on disk), so pictures also have a copy button: `copyPicture()` puts a PNG on the clipboard (other formats are turned into PNG; the PNG is a promise inside the `ClipboardItem`, so the write happens within the click). Drop places use `isFileDrag()` and `filesFromDrop()`, which give back files from the computer as they are and queue results read back as `File`s, so a tool can't tell them apart. While a result is dragged, every `DropZone` whose `accept` fits it lights up. "Open in…" (↗ in the rail) lists the tools whose `accepts` take every file of the job (interactive tools that take files set `accepts` too; `'*'` takes anything), then `sendToTool()` leaves the files for that tool and `usePendingFiles()` hands them over on its page: `DropZone` does it by itself; tools that hide it once something is open (Crop image, Organize / Split PDF) or have modes (GIF maker, Encode) take them themselves and pass `claimPending={false}`.

## PDF tools

- **Organize PDF / Split PDF** (`src/tools/pdf/organize/`, `src/tools/pdf/split/`) share a page grid (`src/tools/pdf/pages/`): pictures of the pages drawn by pdf.js only when their card scrolls into view (`thumbs.ts`), picking with Ctrl / Shift, dragging with pointer events (`PageGrid.tsx`) and the list logic as plain functions (`model.ts`). Both save through the worker task `build-pdf`: outputs made of `{ src, index, rotate }` pages (or `{ blank: [w, h] }`); each output copies the pages it needs from a source in one `copyPages` call, so shared fonts and pictures are copied once.
- **Compress PDF** "keep text" (`src/workers/tasks/pdfImages.ts`) only redoes the image XObjects: DCT (JPEG) and 8-bit Flate RGB / gray images (PNG predictors undone, `fflate`) are scaled down and saved as JPEG when that's smaller. CMYK, Indexed, masks, `/Decode` arrays and small Flate images (icons) are left alone. "Redraw pages" draws every page as a JPEG (the old way).
- **Images to PDF** (`src/tools/pdf/scan/`): `scan-detect` finds the sheet's corners (`detectSheet` in `src/workers/tasks/scan.ts`), which can be dragged (`CornerEditor.tsx`); `prepare-page` straightens, flattens and tones the sheet, makes near-white grey pixels pure white and wipes lone specks (`cleanPaper`), turns the page level by its text (`textSkew`: the angle at which counting the top and bottom edges of strokes per row gives the sharpest peaks, so it works without the paper's edges), and for "only what's written" wipes non-white areas joined to the picture's edge (`wipeSurroundings`) and cuts out the ink's box (`contentBox`). The levelling, the wiping and the box are all read from a black and white copy of the page, so grey and colour come out the same as black & white. The sheet is looked for by each pixel's darkest colour first (white paper vs. a light wooden table), with a second Otsu split among the bright pixels, then by brightness; `pages-to-pdf` places each picture with `place()` (`layout.ts`, shared with the page preview): the sheet as wide as the page, the content at its place on it, moved or shrunk only to stay inside the margins.
- **Text recognition**: [tesseract.js](https://github.com/naptha/tesseract.js) 7 (Apache-2.0) in its own worker, with the LSTM-only SIMD core (`tesseract.js-core`) and the `4.0.0_best_int` language files of `@tesseract.js-data/*` (eng, ces, slk, deu, pol, spa, fra). Tesseract wants its language files by name in one folder, so a small plugin in `vite.config.ts` serves them at `/ocr/<code>.traineddata.gz` in development and copies them there in the build. (Passing the data in directly is broken in tesseract.js 7: `initialize` joins `lang.data` instead of `lang.code`.) Failures it only reports to `errorHandler` reject the job instead of leaving it waiting. The words go into the PDF as invisible text (`3 Tr`, stretched to each word with `Tz`) at their place, in [DejaVu Sans](https://dejavu-fonts.github.io/) (free licence, `dejavu-fonts-ttf`) embedded as a subset through `@pdf-lib/fontkit` (MIT), so Czech and other accented letters search and copy right (`src/workers/tasks/ocrLayer.ts`).

## QR code maker

- **Content** (`src/tools/calc/qr/payloads.ts`, plain functions): each kind of content becomes the text phones understand: `WIFI:` (with `\ ; , : "` escaped), vCard 3.0, `mailto:`, `SMSTO:`, `tel:`, `wa.me`, a map link or `geo:` (coordinates are also read out of pasted Google Maps / Mapy.cz / OpenStreetMap links), iCalendar `VEVENT`, QR Platba (`SPD*1.0*…`, a Czech account number is turned into an IBAN and both are checked) or EPC (the European SEPA "GiroCode"), and `bitcoin:` / `litecoin:` / `ethereum:` (amount in wei).
- **Encoding:** [qrcode](https://github.com/soldair/node-qrcode) (MIT), only `QRCode.create()` for the module matrix; it picks the shortest modes itself (numeric, alphanumeric, UTF-8 bytes).
- **Drawing** (`render.ts`): the matrix becomes one SVG in module units: dot shapes (joined ones look at their neighbours: "smooth" rounds free corners, "fluid" also fills the inner corners, lines join runs), the three eyes drawn on their own, solid or gradient fills (`userSpaceOnUse`, so a gradient runs across the whole code), a logo as `<image>` with the modules under it left out (whole modules around the middle), and a frame with a caption. The caption's font goes into the SVG as `@font-face` with the file written in (`fonts.ts`, the @fontsource files the site already has), so it looks the same in the preview, the PNG and the saved SVG.
- **Scan check** (`raster.ts`): the picture is read back with [jsQR](https://github.com/cozmo/jsQR) (Apache-2.0, loaded on first use) the way a camera sees it: on white, at 5–10 px per module and a little blurred (jsQR misses many perfectly sharp pictures, small dots most of all, that it reads once they're soft). Only if that fails it's tried with light and dark swapped (by swapping the pixels; jsQR's own `onlyInvert` doesn't find them).

## Crop image

`src/tools/image/crop/`. The page shows a copy of at most 2048 px (HEIC and TIFF through the `image-preview` worker task); the box is kept in pixels of the full picture as turned, so what's shown and what's saved match. `geometry.ts` holds the box maths (handles with or without a ratio, drawing, nudging, the box following a quarter turn or a mirror, "same crop for all" as parts of each picture) and `step()` keeps any mix of turns and flips as "turn, then maybe mirror". Cropping runs as a queue task through the `image` worker task: `ImagePayload.crop` (and `circle`) turn, cut, resize and maybe cut round the full picture; without `crop` the other image tools work as before.

## Encode, encrypt & hash

`src/tools/dev/crypto/` (it replaced the old Base64 tool; `/t/base64` opens it with Base64 picked). Everything runs in the browser, and passwords and keys are never saved.

- **Encodings and classic ciphers** (`codecs.ts`, `ciphers.ts`, my own code, no library): Base64 / Base32 / Base58 / Ascii85 / Z85 / Base45, hex, binary, octal, decimal, URL, HTML entities, Unicode escapes, quoted-printable, Punycode, Morse code; Caesar, ROT13 / 47 / 18, Atbash, affine, Vigenère, Beaufort, autokey, substitution, Playfair, Polybius, Bacon, A1Z26, rail fence, columnar transposition, XOR and reverse. `methods.ts` lists them as steps (bytes → bytes, with their options), so they chain: decoding runs the steps backwards, each one undone (`runChain`). Text steps read UTF-8 and say so when they get binary data. `detect.ts` guesses what a pasted text is (one click sets the step), and Caesar gets every shift listed.
- **Hashes** (`hashes.ts`): [hash-wasm](https://github.com/Daninet/hash-wasm) 4.12 (MIT): MD5, SHA-1/2/3, Keccak, BLAKE2/3, RIPEMD-160, Whirlpool, SM3, MD4, CRC32/32C/64, Adler-32, xxHash, all of them in one read of the data (a file goes through in pieces), optionally as HMAC. The "compare with" field finds the row a pasted checksum matches (hex or Base64).
- **Password hashes** (`passwords.ts`): bcrypt and Argon2 in their usual encoded form; scrypt and PBKDF2 in the PHC form (`$scrypt$ln=…,r=…,p=…$salt$hash`, `$pbkdf2-sha256$i=…$…`); checking also reads passlib's PBKDF2 hashes (bare rounds, `.` for `+`).
- **Encryption** (`encrypt.ts`): [@noble/ciphers](https://github.com/paulmillr/noble-ciphers) 2.4 (MIT). With a password: AES-256-GCM or XChaCha20-Poly1305 with the key from Argon2id (64 MiB, 3 passes) or PBKDF2-SHA256 (600 000 rounds), in a small format of its own: `"UNKT"`, version 1, cipher, KDF and its settings, salt, nonce, ciphertext with tag; the header is the AAD, so changing it fails like a wrong password. Or OpenSSL compatible: the same bytes as `openssl enc -aes-256-cbc -pbkdf2 -iter N -salt` (`Salted__`, key and IV from PBKDF2-HMAC-SHA256); its Base64 is wrapped at 64 characters, which `openssl -a` needs. With your own key: AES-GCM / CBC / CTR / ECB, ChaCha20(-Poly1305), XChaCha20-Poly1305, Salsa20, XSalsa20 and RC4 (my own, for old data).
- **Worker** (`crypto.worker.ts`, `cryptoClient.ts`): hashing, password hashes and encryption run in a worker of their own, so the page doesn't freeze; "stop" ends that worker and the next job starts a new one.
- **Tests**: a script with the standards' own examples (RFC 4648, 9285, 3492, 4231, 7914, NIST, the usual cipher examples), a round trip of every method with Czech text, emoji and random bytes, and OpenSSL both ways.

## Video & audio downloader (yt-dlp + aria2c)

The downloader tool works like the [Seal](https://github.com/junkfood02/Seal) app: it runs [yt-dlp](https://github.com/yt-dlp/yt-dlp) (Unlicense) on this computer, with [aria2c](https://aria2.github.io/) (GPL-2.0) downloading in 16 connections at once and [ffmpeg](https://ffmpeg.org) (GPL build from [yt-dlp/FFmpeg-Builds](https://github.com/yt-dlp/FFmpeg-Builds)) joining video and sound and embedding covers and subtitles. Content behind DRM (Spotify, Netflix…) isn't supported by yt-dlp.

- **Server part:** `scripts/downloader-server.ts`, a Vite plugin in both the dev and the preview server (so it works with start.bat, not on a static host), under `/api/dl/`: `status`, `install`, `update` (`yt-dlp -U`), `info` (`yt-dlp -J --flat-playlist`), `start`, `job/:id` (progress), `job/:id/cancel` (kills yt-dlp, aria2c and ffmpeg with `taskkill /T`), `job/:id/file/:n` and `job/:id/forget`. Downloads go to `%TEMP%\unktilz-dl\<id>` and are deleted once the page has the files (leftovers on the next start). Node is passed to yt-dlp as its JavaScript runtime (`--js-runtimes node:…`), which YouTube needs.
- **Programs:** "Install" downloads them into `bin/` (git-ignored, left alone by update.bat): yt-dlp.exe checked against `SHA2-256SUMS`, ffmpeg (the `win64-gpl-shared` build, 91 MB) against `checksums.sha256`, and aria2 1.37.0, which publishes no checksums, against a hash pinned in the code. On other systems the programs are used from PATH. Vite doesn't watch `bin/`.
- **Safety:** the API only answers this site's own pages: the `Host` must be localhost, a cross-site `Origin` / `Sec-Fetch-Site` is refused, and every request needs the `X-Unktilz: 1` header (another website can't send it without a CORS preflight, which this server never allows). Arguments go to yt-dlp as a list, never through a shell, and only http(s) addresses are accepted. The "extra yt-dlp options" field refuses options that run programs or write outside the download folder (`--exec`, `-o`, `-P`, `--downloader-args`, `--use-postprocessor`, `--netrc-cmd`, `--cookies`, `--config-locations` … see `checkExtra` in `src/tools/video/downloader/args.ts`).
- **aria2c:** runs with `--disable-ipv6=true` (on connections with an IPv6 address but no IPv6 route it otherwise fails at once with socket error 10051, while yt-dlp falls back to IPv4). If it still exits with an error, the job deletes its half-done files and runs yt-dlp again without aria2c (`fallback` in the job state).
- **Formats:** video as MP4, MKV, WebM, MOV or AVI (MP4, MOV and AVI prefer H.264 + AAC and are only remuxed, never re-encoded; MOV and AVI can't hold subtitles, so they come as files), optionally without sound (`bv`); sound only as MP3, M4A, Opus, OGG (yt-dlp's `vorbis`), WAV, FLAC or the site's own file, with a bitrate for the lossy ones (`--audio-quality 192K`, or `0` for the best VBR). WAV gets the tags but no cover (yt-dlp can't put one in). yt-dlp's `aac` isn't offered: it also makes an .m4a. `optionArgs` only takes values from these lists, whatever the page sends.
- **After a reload** (`src/tools/video/downloader/task.ts`): each download is a resumable queue task (see How the queue works) whose data is the link, the options and, once yt-dlp runs, the server's job id; the history entry is saved there too (`pushSaved`), so it works for a download that finished after a reload.
- **Subtitles:** picked from `info` (`subtitles` / `automatic_captions`). "In the video" is `--write-subs --embed-subs --compat-options no-keep-subs` (with `--write-subs`, yt-dlp otherwise keeps the files after embedding); "as files" / "both" add `--convert-subs srt|vtt`, and the files come back next to the video as more results of the job.
- **Page:** `src/tools/video/downloader/` (`Downloader.tsx`, `api.ts`, `args.ts` with the option → argument logic shared with the server). Each download is a queue task (`addTask`), so the finished file lands in the queue like any other result.

## Background remover (AI)

The background remover runs [BiRefNet_lite](https://github.com/ZhengPeng7/BiRefNet) (MIT) in the browser with [onnxruntime-web](https://onnxruntime.ai) (MIT) 1.30, in a worker (`src/workers/bgremove.worker.ts`): on the graphics card through WebGPU when the browser has it, otherwise on the processor (WASM, single-threaded since the site isn't cross-origin isolated). It uses the 512×512 export [`studioludens/birefnet-lite-512`](https://huggingface.co/studioludens/birefnet-lite-512) in fp16 (98 MB): the 1024×1024 exports run out of memory on WASM, and on some graphics cards (AMD Vega here) fail in onnxruntime's WebGPU shaders. The model downloads from Hugging Face the first time, pinned to a commit and checked against its SHA-256 (`src/tools/image/bg-remover/model.ts`), and stays in Cache Storage (`unktilz-models`). onnxruntime 1.30's WebGPU build needs its **asyncify** wasm; giving it the jsep `.wasm` (or only the `.wasm` without the matching `.mjs`) makes it hang while starting.

The mask is kept as layers (`src/tools/image/bg-remover/mask.ts`): the AI's, the colour picks' (tolerance, connected area by flood fill, feathered edge) and the erase / restore brush on top, so the sliders still work after painting. Brush undo stores only the 64×64 tiles a stroke touched.

## Seed map (cubiomes)

The seed map runs [xpple's fork](https://github.com/xpple/cubiomes) of [cubiomes](https://github.com/Cubitect/cubiomes) (MIT) compiled to WebAssembly. The built `src/workers/cubiomes.wasm` is committed, so `npm install` / `npm run build` don't need anything extra. To rebuild it (e.g. to move to a newer cubiomes commit for a new Minecraft version), install [Zig](https://ziglang.org) (`winget install zig.zig`), update `COMMIT` in `scripts/build-cubiomes.mjs` and run `npm run build:cubiomes`.

## Give & summon command generators

- **Game data** (`src/lib/mc/data/`): items, enchantments, effects, attributes, blocks, mobs and every entity, trimmed from [minecraft-data](https://github.com/PrismarineJS/minecraft-data) (MIT) by `node scripts/fetch-mc-data.mjs [version]`. `entities.json` marks what's alive, so things like boats, arrows and TNT get no health, gear, effects or AI fields (`isAlive` in `src/lib/mc/entity.ts`).
- **Entity NBT** (`entityNbt` in `src/lib/mc/entity.ts`) is shared: a spawn egg's mob and a `/summon` entity are the same `MobSpec`. `/summon` adds facing, motion, tags, fire, riders (`Passengers`, any depth) and the entity's own fields. `buildSummon` writes the command and checks the position (`~`, `^`, numbers; `^` only on all three).
- **Each entity's own fields** (`src/lib/mc/entityExtras.ts`) are data: which entities, which fields (yes/no, number, list, dye color, block with states, colored text, background, item) and how they become NBT. Examples: creeper, villager job and trades, armor stand flags and pose, animal variants, saddle, slime size, TNT, falling block, item, XP orb, text / block / item display. The summon generator's Special tab is drawn from it (`ExtrasEditor.tsx`), so a new field only needs a line there. A field with `since` is left out, with a note, in older versions; `only` limits a field to some entities of its group, and a group with `match` (instead of a list) covers e.g. every mob. A player (a pet's owner) is looked up by name through playerdb.co, or made from the name for offline-mode servers (`src/lib/mc/uuid.ts`). Display turning is given in degrees and written as a quaternion (`quaternion()`, x then y then z).
- **Versions** 1.20.5 – 26.x, checked against the Minecraft Wiki: gear is `ArmorItems` / `HandItems` before 1.21.5 and `equipment` (with the saddle as a slot) from 1.21.5; names and display text are JSON strings before 1.21.5 and SNBT text from 1.21.5.

## Tellraw & title generator

- **Text** is MiniMessage, like the give generator. The parser (`src/lib/mc/minimessage.tsx`) keeps what `<click>`, `<hover>` and `<insert>` do in each piece's style and turns `<selector>`, `<score>` and `<lang>` into pieces of their own (`MSpecial`); `textComponent(…, { interactive: true })` in `src/lib/mc/give.ts` writes them as `selector` / `score` / `translate` parts with `clickEvent` / `hoverEvent` (values, a command with its /) up to 1.21.4 and `click_event` / `hover_event` (`url`, `command`, `page`, `value`) from 1.21.5. Item text (give) doesn't pass `interactive`, so it stays as it was.
- **Commands** (`src/lib/mc/tellraw.ts`): `/tellraw` and `/title` take raw JSON up to 1.21.4 and SNBT from 1.21.5; a title is `times`, `subtitle`, then `title` (the title command shows what was set before it).
- **Page** (`src/tools/minecraft/tellraw/`): `ClickHoverBar.tsx` wraps the selected text in the tags (arguments quoted when needed) next to the shared `MiniToolbar`; the target picker (`src/tools/minecraft/targets.ts`) is shared with the give generator.

## Setblock & fill generator

- **Block states** (`src/lib/mc/data/blockStates.json`, made by `scripts/fetch-mc-data.mjs`): each block's states with their values and the default (worked out from minecraft-data's `defaultState`: the last state changes fastest, booleans go true, false); blocks with the same states share one entry. minecraft-data gives signs and banners a default rotation of 8, so a picked state always goes into the command, even when it equals the default, and the page shows no default for `rotation`.
- **Commands** (`src/lib/mc/blocks.ts`): `blockArg` writes `id[states]{data}`; `blockDataNbt` the block entity data for signs (`front_text` / `back_text` with JSON or SNBT lines; click commands add `allow_op_features` from 1.21.5), containers (`Items`, `LootTable`, `CustomName`, `Lock` until 1.21.1 or the `lock` item predicate), spawners (`SpawnData` from `entityNbt`), command blocks, heads, beacons, jukeboxes and lecterns. `buildBlock` checks positions, the version's options (`strict` and a mode after `replace <filter>` from 1.21.5) and splits a fill bigger than 32,768 blocks into a grid of pieces (whole height first) when both corners are given the same way.
- **3D view** (`src/tools/minecraft/setblock/`, three.js, loaded with the tool): `blockView.ts` turns the settings into what to draw (the area in blocks from where the command runs, `^` as if looking south, how it's filled, the pieces of a split fill read back from its commands, a rough color from the block's name); `blockScene.ts` draws it (a box whose texture repeats once per block, the side lengths as sprites that keep their size on screen, a ground grid on whole blocks) and `playerModel.ts` the player at `~ ~ ~`: a 64×64 skin drawn as pixel art in the code (hair, beard, shirt, trousers) on boxes laid out like the skin editor's (`box3d` / `faceFrame` / `faceRect`), 1.8 blocks tall and `Block3D.tsx` adds dragging and zoom.

## Resource pack maker

- **The game's files** (`src/lib/mc/pack/vanilla.ts`): the version list comes from Mojang's `version_manifest_v2.json` (releases from 1.20.5) and the client jar from piston-data; both send `Access-Control-Allow-Origin: *`, so the browser downloads them itself. The player can also pick the jar from `.minecraft/versions/<version>/` (offline). The worker task `mc-jar-assets` (`src/workers/tasks/mcJar.ts`) keeps only what a pack uses from `assets/minecraft/` (textures, models, items, blockstates, atlases, texts, equipment, `lang/en_us.json`): about 5–6 MB of the 40 MB jar, stored in IndexedDB (`unktilz-mc-vanilla`, at most two versions). The pack format is read from the jar's `version.json` (`pack_version.resource_major/minor`, or `resource` before 1.21.9), so newer versions need no code change; `KNOWN_FORMATS` lists the older ones for "also works in".
- **Pixels** (`src/lib/mc/pack/pixels.ts`): PNGs are decoded and encoded here rather than through a canvas, which keeps colors premultiplied and would shift see-through pixels (glass, water). `decodePng` reads every color type and bit depth the game uses (palette with tRNS, gray, RGB with a transparent color, alpha); it was checked against the browser on all 3,964 textures of 26.3. `encodePng` writes a palette PNG when there are at most 256 colors (nearly always), otherwise RGBA with a per-row filter, and reads back exactly. Painting tools, color adjustments and scaling work on `{ w, h, data }` of any size; animations are edited one frame (a square of the strip) at a time.
- **The pack** (`src/lib/mc/pack/pack.ts`): `PackDoc` holds only what the player changed (textures by path, icon, name, MiniMessage description) plus the files of an opened pack it doesn't edit, written back unchanged. `packMcmeta` follows minecraft.wiki: from format 65 (1.21.9) `min_format` / `max_format`; a pack that also covers older formats adds `pack_format` and `supported_formats` with the same major versions. A changed texture gets the game's `.mcmeta` next to it (animation, mipmap settings), without the animation when the new picture has one frame. Work in progress is kept with `useAutosave`; "my packs" go into the backup.

- **3D view** (`src/lib/mc/pack/models.ts`, `src/tools/minecraft/resource-pack/modelScene.ts`, three.js loaded with it): `previewModel` finds the block model that uses a texture (the one named like it, else the shortest name; 26.x texture entries can be `{ sprite }` objects) and resolves parents and `#` names; faces get the game's default UVs, rotations, element rotation with rescale, tint for `tintindex` faces and the game's side shading. Items are flat models one pixel thick (front, back and an edge per pixel). The texture being painted is drawn live; a broken model shows a note instead (its own `ErrorBoundary`).
- **Animations** (`src/lib/mc/pack/anim.ts`): frames are squares under each other; duplicating, deleting and moving frames rewrites a `frames` order list so it plays the same pictures. The preview plays them with `frametime` (ticks of 50 ms) and `interpolate`.
- **Ready-made changes** (`src/lib/mc/pack/tweaks.ts`): lower fire, clear glass, clearer water, see-through pumpkin, no vignette, softer glint, lower shield. Each changes the loaded version's own file when the pack is built; a texture the player changed by hand wins.
- **Own items**: `assets/<namespace>/textures/item/<id>.png`, `models/item/<id>.json` (what `item_model` names in 1.21.2–1.21.3) and `items/<id>.json` (1.21.4+); a pack that also covers versions before 1.21.2 gets the base item's model with a `custom_model_data` override. `giveCommands` builds the /give for each case with the give generator's `buildGive`. `unktilz.json` at the pack's root lists the items and changes, so opening the pack again gives them back.

- **Sounds, other languages, the menu panorama** (`src/lib/mc/pack/assets.ts`): these aren't in the jar (it only has 1×1 stand-ins for the panorama) but are Minecraft's asset objects. The asset index comes from piston-meta (CORS); the files from resources.download.minecraft.net through the `/mc-assets/<2 hex>/<sha1>` pass-through in `vite.config.ts` (that host sends no CORS headers). Each file is checked against its SHA-1 (so the pass-through can't hand out anything else, and a static host without it is told apart), and files up to 2 MB are kept in IndexedDB (`unktilz-mc-assets`).
- **Sounds**: own sounds are converted with ffmpeg (`toMinecraftOgg` in `src/lib/mc/pack/sound.ts`) to Ogg Vorbis, 44.1 kHz, mono (the game can only place mono sounds in the world; `music.*` stays stereo and is streamed), with a trim and volume. They go to `assets/<namespace>/sounds/custom/<event>/<n>.ogg` and `sounds.json` points the event at them with `replace: true`, keeping the game's subtitle.
- **Texts**: `assets/minecraft/lang/<code>.json` with only the changed keys (the game merges language files); English comes from the jar, the 140 other languages from the asset objects. Splash texts: `texts/splashes.txt`, the game's lines plus the player's, or only the player's.
- **Menu background** (`src/lib/mc/pack/panorama.ts`): six faces, 0 front, 1 right, 2 back, 3 left, 4 up, 5 down; up's bottom edge and down's top edge touch the front. That layout was checked on the game's own panorama (its edges line up only this way) and on converted pictures. A 360° photo is turned into the six faces in the compute worker (`mc-panorama`), and `PanoramaView.tsx` shows them the way the title screen does (85° lens, slowly turning). The parts of the pack are in tabs: textures, own items, ready-made changes, sounds, texts, menu background.

## Settings and themes

`/settings` (`src/pages/Settings.tsx`, "settings" in the header) holds the theme, the language, the update check and a few facts (version, where saved things live, Ctrl+K). Themes are sets of the color variables in `src/styles.css` under `[data-theme='…']` (`--bg`, `--surface`, `--fg`, `--accent`, `--warn`, `--info`…); `src/lib/theme.ts` lists them and sets `data-theme` on `<html>` (a script in `index.html` does it before the page draws, so nothing flashes). "Follow system" is the default and picks dark or light from `prefers-color-scheme`. The previews in Settings carry their own `data-theme`, so they show their colors on any page. New colors in CSS should use the variables; 3D views read them with `getComputedStyle` when the theme changes (`useTheme()`). To add a theme: a block in `styles.css`, its id in `THEME_IDS` and `index.html`, and its name in `themeName`.

## Versions and updates

The version lives in `package.json` and every change is listed in `CHANGELOG.md` (newest first, `## [x.y.z] - YYYY-MM-DD`). The middle number goes up for new features, the last one for fixes. The site shows its version in the footer and on the Settings page; the Changelog page (`/changelog`) and Settings have a "Check for updates" button (`src/components/UpdateCheck.tsx`) that compares it with `package.json` on GitHub, and the header shows "update available" when there's a newer one (checked at most once a day). Updating is a double-click on `update.bat`; saved items stay because they live in the browser. After an update, a "What's new" popup (`src/components/WhatsNew.tsx`) shows the changelog entries since the version last seen in this browser (kept in `localStorage`), once.

Each changelog entry starts with a short list of the main points (at most about six), then `### Added` / `### Changed` / `### Fixed` with the details. `changelogSections` (`src/lib/updates.ts`) splits an entry there: the changelog page and the popup show the short list, and the details fold under "details".

Saved items and work in progress are kept in IndexedDB per address (always `localhost:5173` with `start.bat`). `/backup` downloads them as one JSON file and loads them on another computer.
